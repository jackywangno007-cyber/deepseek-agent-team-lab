# AGENTS.md

## Project Goal

DeepSeek Agent Team Lab is an educational local multi-agent collaboration system. V0.1 validates Manager-Workers methodology through a command-line pipeline that produces durable project artifacts. V0.2 adds a local FastAPI service around the same runtime.
V0.3 adds a React visualization UI that consumes the API and WebSocket stream.

Do not turn this project into a simple multi-agent chat demo. The source of truth is the artifact workspace, not a conversation transcript.

## Repository Structure

```text
backend/
  api/         FastAPI app, routes, schemas, and WebSocket endpoint
  agents/      role-based agents
  core/        LLM client, workspace, events, orchestration, evaluation
  prompts/     prompt templates
  services/    thin service layer between API and core runtime
  schemas/     Pydantic models
docs/          design notes
examples/      example task inputs
frontend/      React/Vite local dashboard
tests/         pytest suite
workspace/     generated task runs
```

## Run Commands

```bash
python run_task.py --task "Design an MVP for a student course management system" --mock
python run_task.py --task-file examples/task_student_course_system.md --mock
python run_task.py --task "Design an MVP for a student course management system" --model deepseek-v4-flash
python run_server.py
cd frontend && npm run dev
```

## Test Commands

```bash
pytest
```

## Coding Conventions

- Use Python 3.10+.
- Keep modules small and beginner-friendly.
- Prefer standard library, Pydantic, Rich, python-dotenv, and the OpenAI SDK.
- Use UTF-8 for all file operations.
- Keep paths cross-platform with `pathlib`.
- Do not hard-code secrets.
- Do not print API keys or include them in errors.

## Agent Design Principles

- Every agent must have clear responsibility boundaries.
- Every agent declares `input_artifacts` and `output_artifact`.
- Agents should not freely read or write all files.
- Every intermediate result must be saved as an artifact.
- Every important action must be logged as an event.
- The reviewer must use concrete scores, checklists, and revision items.
- The manager coordinates; workers produce focused deliverables.

## V0.2 API Development Rules

- Keep FastAPI as a thin service layer.
- Do not duplicate agent logic in API routes.
- API routes should call `TaskService`.
- Keep `workspace/` as the source of truth in V0.2.
- Store task metadata in `task_meta.json`; do not add a database yet.
- Keep CLI and API both working.
- Do not expose API keys in responses or logs.
- WebSocket streaming should read `events.jsonl`; avoid complex infrastructure in V0.2.

## V0.3 Frontend Development Rules

- Keep the frontend as an API consumer.
- Do not duplicate backend orchestration, evaluation, workspace, or artifact logic.
- Keep API calls centralized in `frontend/src/api/client.ts`.
- Keep agent status derivation in `frontend/src/utils/agentStatus.ts`.
- Human feedback must be persisted.
- Revision must be logged.
- Never overwrite an artifact without backup.
- Keep revision logic explicit and easy to understand.
- Do not add pause, resume, or message-to-agent controls beyond the V0.3 revision workflow.
- Do not introduce a frontend state framework unless the UI complexity truly requires it.
- Keep CLI, API, and frontend working together.
- Do not expose API keys in browser-visible code or responses.

## Things Not To Do

- Do not add LangChain, CrewAI, AutoGen, or LangGraph in V0.1.
- Do not build a frontend in V0.1.
- Do not add Docker, Kubernetes, Matrix, MinIO, or GitHub integration in V0.1.
- Do not introduce a database in V0.1.
- Do not introduce a database in V0.2.
- Do not add human intervention controls in V0.3.
- Never automatically execute shell commands generated by users or agents.
- Never expose API keys.
- Do not replace artifact collaboration with a chat-only flow.

## Done Definition

A change is done when:

- Mock mode still runs without an API key.
- `pytest` passes.
- Generated task directories contain all required artifacts.
- API-created task directories contain `task_meta.json`.
- Frontend builds with `npm run build`.
- Events are written to `events.jsonl`.
- The evaluator writes `evaluation.json`.
- The code remains readable enough for someone learning agent architecture.
