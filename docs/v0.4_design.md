# V0.4 - Evaluation-driven Agent Improvement

V0.4 should upgrade the system from:

```text
human manually finds problems and requests revisions
```

to:

```text
the system helps identify problems, proposes revision actions, and lets the human approve them
```

## V0.4 Goal

Build an evaluation-driven improvement loop for the multi-agent collaboration system.

The system should:

1. Parse ReviewerAgent findings and evaluator results.
2. Generate structured improvement suggestions.
3. Map each issue to a responsible agent and artifact.
4. Show suggested revisions in the frontend.
5. Allow the human to approve, reject, or edit suggested revisions.
6. After approval, trigger the existing V0.3 revision workflow.
7. Track improvement history.
8. Compare evaluation results before and after revision.

## Why V0.4 Matters

V0.3 gives humans manual control over artifact revision. That is an important step, but it still depends on the human noticing issues, deciding which agent owns the problem, and writing revision feedback from scratch.

V0.4 should make the system more proactive without removing human control. The system can inspect review findings and evaluation results, propose concrete improvement actions, and keep the human in the approval loop before anything changes.

The result should feel like a lightweight AgentOps assistant: observable, controllable, and increasingly helpful.

## V0.4 Workflow

1. User creates a task.
2. Agents generate artifacts.
3. ReviewerAgent writes `review_report.md`.
4. Evaluator writes `evaluation.json`.
5. User clicks "Generate improvement suggestions".
6. System extracts issues and proposes structured suggestions.
7. Each suggestion contains:
   - issue summary
   - responsible agent
   - target artifact
   - proposed feedback
   - severity
   - reason
8. Human approves, rejects, or edits a suggestion.
9. Approved suggestion becomes human feedback.
10. Existing V0.3 revision workflow runs.
11. System compares evaluation before and after revision.

## V0.4 Constraints

- Do not fully automate revisions without human approval.
- Do not add a database yet.
- Do not add authentication yet.
- Do not execute shell commands.
- Do not expose API keys.
- Reuse the V0.3 revision workflow.
- Keep workspace as the source of truth.
- Keep the system local-first.
- Keep mock mode working.

## V0.4 Success Criteria

V0.4 is successful when:

- The system can generate improvement suggestions from review and evaluation outputs.
- The user can approve a suggestion.
- An approved suggestion triggers the revision workflow.
- A rejected suggestion is recorded.
- Evaluation comparison is visible.
- All actions are logged.
- `pytest` passes.
- `npm run build` passes in `frontend/`.

## Open Design Questions

- Should issue extraction be rule-based in V0.4, LLM-based, or a hybrid?
- Should suggestion severity use fixed levels such as `LOW`, `MEDIUM`, and `HIGH`?
- Should evaluation comparison be a simple before/after JSON diff or a user-friendly summary?
- Should approved suggestions create regular `human_feedback.jsonl` records, or a separate suggestion-linked feedback record?
